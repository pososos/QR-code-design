C / 模型設計實驗 · 與線上預測分開
標題／目錄→多語言檢索模型
比較文件與用途描述→ 證據不足內容檢索＋重排模型
逐對評估候選用途→候選或棄權
先標題、再目錄，最後才用內容；重排僅在內容階段。這是用途分類的離線實驗，與上方搜尋服務的候選重排用途不同。


為什麼把分類與檢索分開？
分類協助整理；搜尋仍跨類別，避免分類錯誤讓文件永遠找不到。
為什麼保留人工關卡？
弱標籤和模型分數都只是建議；圖譜關係需連回原文證據。
新增文件怎麼處理？
先識別內容與版本，再更新相關解析與衍生快取。現有小規模實作仍需明確執行索引更新。
探索各模組的輸入與輸出
本頁：可立即操作
檔案讀取、七類規則計分、人工確認模擬、範例搜尋。GitHub Pages 無模型後端；模型展示服務另提供同站推論，人工確認仍僅保留在本次頁面。
本機：已實作能力
自訓 TF-IDF 分類、多語言檢索模型與重排模型、圖譜人工關係與時間軸。

04 / VALUE & ROADMAP
這次展示證明了什麼，
下一步缺什麼。
2026-09-14 更新
求職展示的重點不是「分類很準」，而是工程方法本身可重跑、可稽核、敢公開弱點。這裡直接說明目前 LLM 輔助標註實驗實際證明了什麼能力，以及往後推進真正缺的東西。




可稽核的標註來源
暫緩人工標註期間，改由 LLM 直接讀 240 份文件標題與內容片段判斷用途，寫入獨立 reviewer 身份，與既有 12 份人工標籤全程分開稽核，可追溯是誰、何時、依據什麼判斷，不覆寫既有人工結果。


同一測試集頭對頭比較
把規則式弱標籤、LLM 標籤訓練的分類器、純檢索、檢索＋重排四種方法放進完全相同的測試文件比較；過程中抓到並修正一個真實的資料洩漏 bug（評估用的模型不小心看過答案）。這種可重現的比較方法，本身比任何單一準確率數字更能代表工程能力。


誠實揭露負面結果
檢索＋重排在較大樣本（n=81）反而讓「有答案時準確率」從 81.5% 掉到 65.7%，還慢了約 56 倍；目前沒有證據支持「加了重排一定更好」。公開承認這件事，比只秀成功案例更接近真實的工程判斷過程。






還缺什麼
目前所有分類成效數字（macro-F1 約 0.6–0.7）都建立在 LLM 自己標的資料，或僅 12 筆既有人工標籤之上；樣本量與代表性都不足以宣稱正式成效，只能當作方法可行的訊號。


下一步最關鍵的事
需要真實代表性資料快照與獨立人工測試集才能真正驗證，這是資料問題而非模型或工程問題，無法用更多 LLM 標註繞過；人工標註一旦恢復，會與 LLM 標籤分開稽核比較，不自動視為同一信度等級。


其餘規劃中方向
知識圖譜正式化、時間軸擴充、檢索與重排在更大樣本下的重新驗證，都待資料到位或使用者明確需求後再推進；目前規模不足以支撐任何一項的正式結論。
