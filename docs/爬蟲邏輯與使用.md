# 爬蟲程式邏輯與使用

核心：[crawl.py](../cement/crawl.py)；資料層：[store.py](../cement/store.py)；設定：[sources.json](../sources.json)。

Skill 是操作指引，Python 是實際執行核心：Skill 選來源與參數、執行程式、解讀結果；程式下載與記錄。分類模型不參與目前爬蟲，LLM 也不逐份掃描。

## 呼叫順序

```text
main() 讀來源與 CLI
  └─ Crawler.run(source) 建立 deque 與 seen
       ├─ allowed(url) 篩 HTTPS 主機
       ├─ 讀 sources 舊 ETag / Last-Modified
       ├─ fetch(url)
       │    ├─ permitted(url) 讀取／快取 robots
       │    ├─ wait(url) 控制每站頻率
       │    └─ HTTP GET → redirect / 304 / 串流內容
       ├─ 檢查 PDF、HTML、存取挑戰頁
       ├─ SHA-256 → raw 檔案 → SQLite
       └─ HTML 連結符合條件則加入 deque
```

### main：執行入口

argparse 讀取 --config、--source、--max-files、--delay、--max-mb。JSON 清單選出來源，建立共用 Crawler，依序呼叫 run。多來源目前依序處理，不是平行下載。

### allowed：限制抓取範圍

只接受 HTTPS、完整主機名稱符合 allowed_hosts、沒有 username、port 為預設或 443 的 URL。主機採精確比對，並非網域後綴。重導向後再次檢查，不能藉 redirect 自動擴大到其他主機。

### permitted 與 wait：網站規則與限速

每個主機首次取得 /robots.txt；200 解析、404 視為無規則，其他狀態視為無法確認並失敗。規則與 crawl-delay 在同一 Crawler 內快取。

wait 以 monotonic 計算距離上次請求的時間，等待設定 delay 與 robots crawl-delay 中較大的值。預設 2 秒，CLI 最低 1 秒。

### fetch：下載

HTTP timeout 為連線 10 秒、讀取 60 秒，並非整個工作最多 60 秒。redirect 自行处理，最多六輪；轉址時清除原有條件標頭。304 回傳 body=None 表示未變更。

一般回應每次讀 65,536 bytes，累積進 bytearray；超過 max_mb 換算的 MiB 上限即失敗。這是分塊讀取但不是直接串流落盤，因此記憶體仍需容納整份文件。

### run：佇列、去重與保存

deque 儲存 (url, depth)，popleft 形成廣度優先走訪。移除 URL 的 fragment，seen 防止同來源本次重複訪問。同一來源的唯一排程 URL 達 max_files 時停止；它不等於成功下載數，也不是總 HTTP 請求上限。

末層來源若已有 etag／modified，送 If-None-Match／If-Modified-Since。入口頁若仍需發現連結，重新下載以免遺漏新連結。

檢查 body 是否以 %PDF- 開頭，或回應 Content-Type 為 HTML；已知挑戰頁標記直接拒收。僅辨認少數特徵，不能保證攔下所有反爬頁。

以內容 SHA-256 命名 raw 檔案：相同內容即使不同網址也共用一份。先寫 .part，再 replace 成正式檔，降低半成品被當成完整檔案的風險。

SQLite 寫入三種資料：documents 存文件 hash/路徑/狀態；sources 存來源網址、來源 ID、目前文件、ETag、授權和建議標籤；events 存 saved、unchanged 或 error。相同 URL 變更內容時 sources 更新指向，舊檔仍保留，尚未建立完整版本關係。

HTML 且 depth 未達 max_depth 時，用 BeautifulSoup 找 a[href]，以 urljoin 處理相對網址，使用 link_pattern 比對「網址＋連結文字」後排入佇列。沒有瀏覽器執行 JavaScript。

## 使用命令

在 Windows PowerShell、專案根目錄執行：

```powershell
Set-Location -LiteralPath 'D:\QR code design'
# 指定來源，小量抓取
.venv/Scripts/python.exe -m cement.crawl --source fhwa-scm --max-files 1
# 所有設定來源，各最多三個排程 URL
.venv/Scripts/python.exe -m cement.crawl --max-files 3
# 較大的台泥公開報告
.venv/Scripts/python.exe -m cement.crawl --source tcc-2022 --max-files 1 --max-mb 50
# 下載後另行解析文字
.venv/Scripts/python.exe -m cement.parse
# 啟動文件清冊／標註頁
.venv/Scripts/python.exe -m uvicorn cement.api:app --host 127.0.0.1 --port 8000
```

重跑相同爬蟲命令即可檢查更新：伺服器若支援條件請求，可省下載；否則仍下載再用 hash 去重。不是每次重跑都零網路成本。

## 來源設定範例

```json
{
  "id": "fhwa-scm",
  "url": "https://www.fhwa.dot.gov/pavement/concrete/pubs/hif16001.Pdf",
  "allowed_hosts": ["www.fhwa.dot.gov"],
  "suggested_label": "guidance",
  "license": "Check document-specific terms",
  "max_depth": 0
}
```

這是直接 PDF；max_depth=0。入口列表頁則設定 max_depth=1，並用 link_pattern 限縮欲追蹤連結。例如 Cemex 設定是 `(?i)(cement|clinker)`，但先前實抓遭挑戰頁攔截，不能視為已成功的連結發現示範。

suggested_label 不會自動變成人工 label。取得內容後必須確認用途；文件內容与來源網域可能不一致。

## 如何判定成功

原文在 data/raw，解析文字在 data/text，來源與事件在 data/catalog.sqlite。管理頁顯示文件與狀態。

- saved：下載／入庫流程完成，不代表新內容，也不保證解析或領域正確。
- unchanged：伺服器 304；本次沒有重取內容。
- error：檢查 detail；主程序仍可能正常結束。
- parsed：初步文字檢查通過；需人工確認用途。
- needs_review／needs_ocr：品質待處理，不訓練。
- blocked_content／out_of_scope：保留稽核，不訓練。

現況是有界資料取得原型。未具備自動重試排程、OCR、JS 渲染、完整版本／刪除同步、TB 級吞吐或語意選材能力。更完整維護細節見 [README_技術維護.md](../README_技術維護.md)。
