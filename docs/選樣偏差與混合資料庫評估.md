## 研究依據及適用界線

[WILDS（ICML 2021）](https://proceedings.mlr.press/v139/koh21a.html)研究真實領域／時間／環境分布位移，支持依部署場景設計評估；不是水泥檔案研究，未提供此專案應有類別比例或樣本數。

[scikit-learn資料洩漏說明](https://scikit-learn.org/1.5/common_pitfalls.html)指出測試資訊滲入模型建構會產生過度樂觀估計，支持先隔離測試、僅以訓練資料fit前處理。本地採用專案／研究計畫／課程／產品家族分組，是針對已觀察來源關聯的設計判斷，並非上述研究證明的唯一最佳切分。

因此：固定範圍收取而非用途搜尋；保持真實類別比例；開發集调參、獨立測試最後才評估。每類65／2:8仍只是訓練規劃，不約束自然測試分布。沒有真實資料夾之前，不能宣稱已建立代表性測試集。

## 收集與評估規則

1. 先由使用者指定公司專案及研究計畫的固定快照範圍，整批列舉全部檔案，包含雜項、掃描、未知副檔名；不先挑好讀或易分類的文件。不能將1+3混合解讀為50:50，尚無真實比例。
2. 先確認專案／研究家族與開發資料無重疊，再冻结清冊、seed及樣本；不按七類補齊測試數量。不為改善結果替換難例。學校／廠商子網域、翻譯、版本、同內容不同檔名需人工／後續相似性檢查。
3. 標題→目錄→正文仍是正式流程；分別評估正常資訊可用、只有正文的壓力測試。不能把隱藏標題的壓力集當自然分布。
4. 保留解析失敗作端到端覆蓋率分母；在可解析資料上另報macro-F1、各類precision/recall、混淆矩陣、棄權率與非棄權錯誤率，按來源／語言／格式分層。數字不足時報樣本數，不宣稱穩健。
5. 人工標註時隱藏模型／來源suggested_label。正式test不參與門檻、類別描述、規則修改；反覆檢視後改作開發資料。現有舊資料一律不重新包裝成新的盲測。

## 已實作工具

cement.local_inventory：針對使用者指定root，不按副檔名篩選，以1MiB串流算hash，記錄讀取失敗與修改中檔案；不追蹤symlink/junction，輸出需位於來源快照外且不可覆寫。會完整讀取檔案計算hash，因此不是TB低成本抽樣，應先用有界專案快照。檔名與路徑保留本機，不上傳。

cement.evaluation_intake：接收先完成的inventory，記錄全清冊hash與seed，再按seed+定位資訊hash確定性選取最多limit份；不讀取用途、分數或標題欄位。支援HTTPS URL或本機绝對path+sha256，拒絕重複定位、已曝光來源主機或已知本機內容hash。limit預設50只是CLI起點，不是統計推薦；實際需預先指定。未保證按family防洩漏，organization/family_id仍需人工跨集核對；本機hash由清冊提供，冻结器不重新讀檔驗證。未下載、未解析、未自動分配正式test或寫入訓練清冊。失敗清單隨結果保存。

```powershell
.venv/Scripts/python.exe -m cement.local_inventory --root 'D:/指定專案快照' --organization '機構識別' --family-id '專案識別' --output data/reports/new-local-inventory.json
.venv/Scripts/python.exe -m cement.evaluation_intake --inventory data/reports/new-local-inventory.json --seed '預先固定的種子' --limit 50 --output data/reports/new-frozen-intake.json
```

上例含佔位路徑，未實際讀取任何使用者公司資料。單次root視為同family；多專案應分別建立清冊，再合併保留各自family，不能自動把不相關文件全部當同一研究計畫。
