# 三分鐘 QR Demo 腳本

2026-09-13。目的是求職展示 Python／JavaScript 全端與資料工程能力，不是展示已驗證的分類成效——分類成效仍待真實代表性資料（見 [D-007](README_總體架構.md#d-007-選樣偏差修正2026-09-13)／[D-008](README_總體架構.md#d-008-雙軌推進與配額延後2026-09-13)）。QR 只是集合入口，重點在後面的資料流程與架構。

## 事前準備（不計入 3 分鐘）

1. 啟動服務。同機展示用 127.0.0.1 即可；要讓手機掃碼須綁 0.0.0.0：

```powershell
Set-Location -LiteralPath 'D:\QR code design'
.venv/Scripts/python.exe -m uvicorn cement.api:app --host 0.0.0.0 --port 8011
```

2. 找本機區網位址（供手機同 Wi-Fi 連線；每次開機或換網路可能變動，展示前重新確認）：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' }
```

2026-09-13 記錄值（僅供參考，不保證仍有效）：Wi-Fi 介面 192.168.1.109。手機與筆電須在同一網路；沒有登入與權限隔離，不要在公開網路上這樣展示。

3. 若要示範搜尋，先重建索引（新文件或重解析後才需要）：

```powershell
.venv/Scripts/python.exe -m cement.search reindex
```

4. 開啟 `http://127.0.0.1:8011/`（或改用區網位址）確認頁面與 QR 圖正常顯示，再開始計時。

## 腳本（約 3 分鐘）

| 時間 | 內容 |
|---|---|
| 0:00–0:20 | 開場：水泥領域文件工作台原型；QR 是集合入口，重點是後面的資料流程與自訓分類模型架構，不是 QR 本身的花樣 |
| 0:20–0:50 | 掃 QR（或直接開網址）進管理頁：說明「收集公開文件、確認用途、建立可追溯分類資料」；指出目前文件數與狀態分布（parsed／needs_review／…） |
| 0:50–1:20 | 關鍵字搜尋：輸入例如「hydration」，說明搜尋刻意不用分類篩選——避免分類誤判造成永久漏檢 |
| 1:20–2:00 | 開啟 `/review`：示範選一份文件、看片段預覽、選用途、填審核者與群組；強調人工標籤與規則建議分開、來源隔離避免版本／近似文件洩漏 |
| 2:00–2:30 | 開啟 `/graph`：說明這是知識圖譜銜接的起點——規則抓因果詞句產生候選，全部待人工接受或拒絕，因果詞命中不代表已證實因果 |
| 2:30–3:00 | 收尾誠實聲明：目前分類成效只做過內部小樣本診斷（n=12，macro-F1 僅供流程驗證，不是可信賴的成效數字）；正式成效需要真實代表性資料，仍在規劃中。求職重點是工程落地：可重跑爬蟲、資料治理、來源隔離訓練、API／前端、測試覆蓋 |

- 沒有真實公司／研究資料夾快照，代表性測試集尚未建立（D-007）。

- localhost 展示僅同機可用；跨裝置展示需同網段，且本機服務沒有登入或權限隔離，不能對外公開部署。
