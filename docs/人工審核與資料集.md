## 填寫方式

每筆保留 document_id、text_hash、current_label；閱讀 pages 與 sources 後填：

| 欄位 | 填寫內容 |
|---|---|
| label | research/manual/guidance/safety/industry；未確認保留空白，匯入會跳過 |
| reviewer | 實際審核者識別；不要代填為已有人審 |
| note | 判斷理由、主要用途、頁碼與疑慮 |
| group_id | 同機構／文件家族的分組 ID；近似版本留同組，例如 fhwa-guidance |
| split | train/validation/test；新文件須先按來源家族規劃，不看測試成效後換組 |

標題中繼資訊可能不準，以文件內容為主。本版不提供 out_of_scope/品質狀態修改或標籤清空匯入；無法判定用途的文件保留空白，不強制分類。

```powershell
.venv/Scripts/python.exe -X utf8 -m cement.review export --output data/reviews/new-batch.json
# 人工填寫後才匯入
.venv/Scripts/python.exe -X utf8 -m cement.review import --input data/reviews/new-batch.json
.venv/Scripts/python.exe -X utf8 -m cement.dataset --output data/reports/new-draft.json
```

匯出與報告檔禁止覆寫既有檔案，請使用新檔名。CLI 不會自動打開編輯器或收集人員資料。

## 程式與資料表

- cement/review.py：匯出全文審核包；先驗證全批再匯入；文字 hash 防過期、current_label 防覆寫、群組避免跨 split。
- review_log：review_id、document_id、text_hash、label、reviewer、note、created_at。相同匯入冪等。
- dataset_membership：document_id、group_id、split、text_hash、updated_at。已有 group/split 不允許由一般匯入改動；需要日後另做可審核遷移。
- 匯入寫 documents.label；更新相同文件／文字版本弱標籤的 confirmed/rejected，但不將其他未看過文件升級成人工標籤。
- cement/dataset.py：優先人工標籤、弱標籤必須符合當前規則與文字 hash；列出缺口、未分組、待抽驗、失效版本與跨組風險。
- 草稿檢查精確 source host 不跨 split；不等於完整機構辨識。同機構不同子域、轉載、近似版本仍需人工 group_id 管理。

## 已知限制

資料集工具目前固定 draft_only=true / training_ready=false，直到後續有受控弱標籤抽驗與混合訓練流程才啟用。pending 弱候選不算 ready 數量；2:8 目標只是缺口展示，沒有抽樣補足或複製文件。

人工標籤可經旧 API 設定，但沒有 membership 時仍不算草稿 ready。現行 train.py 仍為舊人工訓練 CLI，尚不消費 dataset_membership 或草稿；不要用它冒充已驗證的群組隔離混合訓練。

沒有自動群組推斷、分層隨機抽驗、弱標籤群組放行、sample_weight 或審核 UI。本階段先確保人工輸入與資料一致性，因現有資料只有三份 parsed、無人工真值，不足以驗證混合模型。

## 決策 D-002：審核先行與群組隔離

- 問題：如何把人工標籤接入後續資料集，避免錯誤覆寫與評估洩漏？
- 研究：[Snorkel](https://pmc.ncbi.nlm.nih.gov/articles/PMC7075849/)描述人工 development set 與 blind held-out labeled test set。可支持独立人工評估的需求，不決定本案樣本量或 JSON 格式。
- 官方實作參考：[scikit-learn grouped cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)說明同群組資料的隔離，作為本案 group/split 一致性檢查的參考，非水泥領域實驗。
- 查核日期：2026-09-12；查核相關頁面搜尋摘要與官方文件條目，未重現研究實驗。
- 工程設計：hash 防過期、原子匯入、空白標籤跳過、凍結既有 split、只輸出草稿，是本地一致性與小樣本限制下的可逆選擇，無研究聲稱這些具體設計最優。
- 未採方案：按文件隨機 8:2 切分（可能跨家族洩漏，且混淆人工／弱標籤比例）；直接把 candidate 寫入人工欄位（破壞來源真實性）；立即混合訓練（沒有足夠人工評估資料）。
- 本地驗證：13 項測試通過，新增四項涵蓋真值保護、過期原子匯入、群組衝突、冪等與草稿失效排除；只驗證功能。
- 重評：樣本與人工評估集足夠時，新增弱標籤抽驗政策、跨來源訓練與加權比較；再決定何時允許 training_ready。

## 精簡人工標註工作包（2026-09-12）

[cement/review_pack.py](../cement/review_pack.py) 將匯出的全文 JSON 轉成離線 Markdown 閱讀文件及精簡標註 JSON。無新增套件；目錄必須不存在，防止覆寫已填內容。既有 label/reviewer 等欄位原樣保留，不自動產生人審結果。

```powershell
.venv/Scripts/python.exe -m cement.review_pack --input data/reviews/batch-20260912-02.json --output data/reviews/reading-pack-20260912-01
# 上述目錄已產生；重跑請另取新目錄。
# 人工讀完逐份全文，填寫 answers.json 後：
.venv/Scripts/python.exe -m cement.review import --input data/reviews/reading-pack-20260912-01/answers.json
# 匯入成功後以新檔名輸出資料集草稿：
.venv/Scripts/python.exe -m cement.dataset --output data/reports/dataset-after-human-01.json
```

入口 data/reviews/reading-pack-20260912-01/README.md；document-001.md 至 document-008.md 為含頁碼全文。answers.json 保留 document_id/text_hash/current_label，人工填 label、reviewer、note、group_id、split。只修改後五欄；空白 label 不匯入。既有匯入器仍核對文字版本與群組衝突。不得將已用於開發的本批宣稱為盲測集。

本輪 15 項測試通過（兩個既有相依棄用警告）。工作包是解析文字快照，無法取代原 PDF 的圖表與版面檢查；若文字不足以判讀，保留空白。沒有修改 train.py 或啟用混合訓練。

## 輔助審核頁面（2026-09-12）

已新增 /review（cement/static/review.html），工作台首頁有入口。列出 parsed 文件，預設顯示有文字的首／中／末頁各最多 1,800 字及原頁碼；可選全文，全文為所有解析頁，圖表仍需來源原檔。五类用途單選；暫不確定可跳過，不寫入標籤。表單在頁面切換時保留暫填內容，重新整理不保留。

填寫審核者、文件群組、資料用途與可選理由後，按「儲存並下一份」寫入資料庫。既有群組／split 凍結。既有 label 會顯示；不呈現弱標籤建議。測試／驗證集不可使用已參與開發文件。

GET /api/review/{doc_id}?full=false|true 回傳頁碼內容、text_hash、current_label 與 membership。POST /api/review 使用 ReviewSubmission，透過 cement.review.import_rows 與 CLI 共用驗證／原子寫入：文字過期、群組衝突回傳 409，欄位不合法 422。舊首頁直接 label API 仍存在；完整審核請使用新入口。

本機啟動：`.venv/Scripts/python.exe -m uvicorn cement.api:app --host 127.0.0.1 --port 8011`，開啟 http://127.0.0.1:8011/review 。僅本機工具，未發布，沒有新增身份驗證。16 項測試通過、JavaScript 語法檢查通過；瀏覽器確認 8 份清單、片段及分類表單。實際儲存測試使用隔離資料庫，沒有替真實文件標註。本次沿用 D-002；1,800 字與三處取樣為可逆 UI 初值，不是研究證實最佳值。
